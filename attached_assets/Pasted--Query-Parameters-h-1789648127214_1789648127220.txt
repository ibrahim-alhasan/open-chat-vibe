أريد تعديل موقع الدردشة ليستقبل بيانات المستخدم من Query Parameters في رابط الصفحة.

مثال الرابط:

https://chat.example.com/?first_name=علي&father_name=محمد&family_name=حسين&theme=dark

المطلوب:

1. عند تحميل صفحة الدردشة، اقرأ القيم التالية من الرابط باستخدام URLSearchParams:

- first_name
- father_name
- family_name
- theme

مثال JavaScript:

const params = new URLSearchParams(window.location.search );

const firstName = params.get('first_name') || '';
const fatherName = params.get('father_name') || '';
const familyName = params.get('family_name') || '';
const theme = params.get('theme') === 'light' ? 'light' : 'dark';

const fullName = [firstName, fatherName, familyName]
  .filter(Boolean)
  .join(' ');

2. اعرض اسم المستخدم داخل واجهة الدردشة بصيغة:

الاسم الأول + اسم الأب + الكنية

مثال:

علي محمد حسين

3. طبّق الثيم القادم من الرابط:

document.documentElement.dataset.theme = theme;

إذا كانت القيمة light يتم تطبيق الوضع النهاري، وأي قيمة أخرى يتم اعتبارها dark.

4. اجعل بيانات الاسم للعرض فقط:

- لا تعرض حقول تعديل الاسم.
- لا تسمح للمستخدم بتعديل first_name.
- لا تسمح للمستخدم بتعديل father_name.
- لا تسمح للمستخدم بتعديل family_name.
- اجعل عناصر الاسم غير قابلة للتحرير باستخدام readonly أو اعرضها كنص فقط.
- لا تقرأ الاسم من حقول يكتبها المستخدم داخل الدردشة.

5. عند إنشاء أو حفظ جلسة الدردشة، خزّن بيانات المستخدم في قاعدة البيانات:

- first_name
- father_name
- family_name
- full_name
- theme

6. لا تثق بالبيانات القادمة من الرابط ثقة كاملة، لأن Query Parameters يمكن تعديلها من المستخدم. يجب تنفيذ التحقق من جهة الخادم قبل حفظها، وليس من JavaScript فقط.

7. الأفضل أن يكون هناك user_id أو معرف مستخدم قادم من الموقع الأصلي، ثم يقوم الخادم بجلب الاسم الحقيقي من قاعدة البيانات بدل الاعتماد على الاسم الموجود في الرابط.

8. إذا لم يتوفر user_id، استخدم البيانات القادمة من الرابط للعرض المؤقت فقط، ولا تعتبرها هوية موثوقة ولا تستخدمها لتعديل سجل مستخدم موجود.

9. يجب منع المستخدم من تغيير بيانات الهوية من خلال:
- إخفاء حقول التعديل.
- تجاهل أي first_name أو father_name أو family_name يرسلها المتصفح في طلبات الحفظ.
- تحديد هذه الحقول من الخادم فقط.
- السماح للدردشة بحفظ الرسائل فقط، وليس تعديل بيانات الحساب.

10. لا تحفظ أي كلمة مرور أو Access Token أو Refresh Token داخل الرابط.

11. أضف رسائل واضحة في الحالات التالية:
- عدم وجود بيانات المستخدم في الرابط.
- وجود قيمة theme غير صحيحة.
- فشل حفظ بيانات الدردشة.
- فشل التحقق من هوية المستخدم.

12. تعامل مع القيم بأمان:
- استخدم textContent بدل innerHTML عند عرض الاسم.
- طبّق escaping إذا كان لا بد من استخدام HTML.
- طبّق حدودًا لطول كل قيمة.
- ارفض القيم التي تحتوي على HTML أو JavaScript.
- لا تسمح بأي XSS.

13. أنشئ دالة موحدة مثل:

getChatUserFromUrl()

تقرأ البيانات وتعيد:

{
  first_name,
  father_name,
  family_name,
  full_name,
  theme
}

14. أنشئ دالة خادمية مثل:

resolveChatUser()

تتحقق من user_id أو الجلسة الموثقة، وتجلب الاسم الحقيقي من قاعدة البيانات، ثم تستخدم البيانات الموثوقة عند الحفظ.

15. عند وجود تعارض بين البيانات القادمة من الرابط والبيانات الموجودة في قاعدة البيانات، استخدم بيانات قاعدة البيانات واعتبر بيانات الرابط غير موثوقة.

نفّذ التعديلات مع الحفاظ على وظائف الدردشة الحالية، وأرسل لي قائمة بالملفات التي تم تعديلها واختبارات التحقق التي تم تنفيذها.
